# Building a No/low-Code Website builder for designers.

## | Product design | UX Design | User Research | Marketing & Branding | Strategy | #Everything-Design-Related |

****Amaze Studio was a sandbox product for creatives – a no-code website builder for the everyday visual designer. In the UX world our quest, often deeply rooted in pragmatism, is to create the simplest, no nonsense, most rewarding of user journeys. The consumerist nature of modern user experience design ensures that it is so. Amaze, was anything but that.

ICD was incubating a start up R Corp that was creating a design engine wich exported theHTML, JS and CSS files. It was to be called Amaze Studio. While there, I worked as the main intern on this project, conducting research to designing investor presentations to the marketing website.

**Client** Itu Chaudhuri Design pvt ltd.

**Role** Design Intern @ ICD: Diploma project under Principal designer Lisa Rath, with the help from UX Head Avi Agarwal.
In partnership with R-corp: Gaurav Ramanan

## The Audit

I realised that the V1 of the software was designed to provide a front end to how code was written. While this product did all that was required from a code generator, it was clunky, hard to use, and a little overwhelming at first with the amount of tools and parameters that it required the users to take care of.

![](../images/AmazeStudio/c10408fb_Old-amaze.png)A screenshot of Amaze Studio 1.0 circa May 2017.

## Diving Deeper

While at ICD and working on the project with the startup, a lot of the research conducted was qualitative in nature. As we were stationed inside a design studio, we had an a few designers as guinea pigs to test our prototypes on, and observe them perform various tasks.

As a starting point to dive deep into the product, I conducted a Heuristic evaluation of the product based on the Nielsen method. I also conducted a fly on the wall study, observing multiple designers using the software. Conducted multiple Interviews regarding how the users went about designing

  * Vector design apps for Print (eg. Illustrator, Indesign)
  * Digital Design softwares (eg. Sketch, Figma,
  * Prototyping tools(eg Invision, Framer)
  * Website builders (eg. Squarespace, wix,)

I conducted a workflow assessment and user journey mapping of how the website would get designed, developed and deployed.

Please note that in this context, when I say design, I specifically mean the visual design of these websites.

## Key Insights from the audit

  * Lack of homing space
  * Lack of responsiveness - need to design multiple times
  * High cognitive load
  * Unfamiliar terminology
  * Tool usage lacked intuitiveness
  * No Shortcuts or Key bindings

![](../images/AmazeStudio/ec5e3290_1a.png)

To begin with we created a 3 step breakdown of the set of tasks the tool needed to perform

  1. **Design :** Ability to design elements in a free manner

  2. **Define :** Ability to define the elements that were created as web friendly entities

  3. **Deploy :** The ability of the tool to cleanly generate a deployable HTML5 CSS + JS code

We conducted a market study to identify and divide our competition and measure how well they were able to fulfil these prerequisites.

## The Amaze Clean up Plan.

While designing amaze we had to make sure that the tool we created never actually overwhelmed the user with a look and feel that would influence in anyway how the user’s creation would look. We had to take into account that the design looked appropriate no matter what the content inside the canvas was and that the Differentiation between the interface and the canvas was prominent enough that the user never felt confused between them.

After creating an IA of the existing tool, we found that many main functions were stuck inside a menu within a menu. The first course of action was to liberate these functions. While working on this, we had a secondary task to introduce functionalities like

  * Responsiveness

  * Save status

  * Preflight

  * Breadcrumbs

  * Zoom Indicator

These were essential and would help the user keep stock of where he was while editing or navigating his designs.

I spent a significant chunk of time to identify the key aspects of each component and create a cleaner Information architecture, something that didn’t suffer from [the kitchen sink effect.](https://www.nngroup.com/articles/hamburger-menus/)

## Version Two Point Oh

One of the key highlights about the redesign was the light theme. After testing it with multiple users, a light theme put lesser cognitive overload on the user, with elements that were easier to pick up for a beginner. Hence we decided to go through with it.

Next up, I had to create an interface that promoted the content that was being designed and strike contrast in the subject and the tool. One of the main strategies to accomplish this was introducing a bottom bar, along with a top, right and left bar. This enclosed the design within a frame and ensured movement within the frame when the user navigated the space.

Lastly, we introduced a toolbox-like toolbar layout, only revealing the most needed tools on the right as we found out that using the toolbar for tools was a beginner behavior that, as the user advanced, would turn into a shortcut dominant behavior.

## Project Conclusion

By the end, since the leaders within the organisations wanted seperate directions, the team decided to sell off the Amaze architecture to one of our competitors, who could incorporate it into their products, a way for Amaze to see the sun someday. One day Amaze will rise again, but today it lays in a state of quiescence.

2021 Update: Looking back, many similar website builders have taken place where amaze couldve once stood. Could be something like Webflow, or something like editorX by wix, or Anima + Sketch, etc; It is possible that you might be using Amaze and not even know it.
